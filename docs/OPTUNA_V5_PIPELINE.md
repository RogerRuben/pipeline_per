# V5：保留V3基线、预测库融合与可恢复训练

发布日期：2026-10-23。保留V2、V3、V4，新增默认V5 `goal_first`。环境继续使用Python3.8.10 x64、sklearn0.24.2、SciPy1.5.4、Optuna3.6.0，无需升级原离线依赖。实体Win7尚未复测。

## 使用入口

完整包解压到较短目录，`START.bat`直接运行已保存的虚拟演示。真实使用时替换`input/products.xlsx`，先`CHECK_INPUT.bat`，再`RETRAIN.bat`。`RESUME.bat`与显式训练入口相同，会根据同数据、同设置、同环境的检查点继续；`START`和`EXPORT`均不训练。

已有离线包：关闭旧程序，把PATCH完整解压覆盖旧包根目录，运行`APPLY_V5.bat`。补丁不覆盖输入表、旧模型或原运行数据库，自定义配置先备份再迁移。`SELECT_V2/V3/V4/V5.bat`或`MODE_MENU.bat`可选择版本与模式。

输入仍为第一行中文名、第二行唯一英文代号、第三行起为记录。只区分数值与配置类型；不同数值量级内部按对应训练子集缩放。专家是**价格属性重要性1—5分**，不是效能分、百分比或最终融合份额。可关闭评分做纯数据对照。最低4条有效正价格记录；训练和验证各至少2条。可选效能/耦合工作表不必填，没有耦合不会自动编造。

## V2/V3日志改进

日志同时显示本轮训练MAPE/R²、开发MAPE/R²、目标优胜模型ID及其对应四项指标。目标优胜用于监控；最终模型仍沿用原Pareto选择规则。

V2用本轮已经拟合的模型预测训练子集；V3缓存训练/验证预测对。没有为了打印训练成绩再fit一遍。CSV及历史记录增加训练指标，旧历史未记录的训练分显示“未记录”；常量训练价格的R²显示“不可定义”，不伪造0或1。

原V2核心保持字节不变，原目标函数、原始初始参数及Pareto选择函数不变。相同虚拟数据300轮前后全部旧试验列、所选参数、开发成绩及1033次搜索成员fit已核对一致。

## V5默认流程

1. **V3基线。** 默认完整执行原V3的300轮研究。不会把300轮拆成几十个局部小研究。保留原冠军，另存训练/开发预测和快照。
2. **轻量融合。** 将同一训练/开发划分中的已拟合成员组成预测库，用非负、和为1的权重求解MAPE，并检验R²和训练门槛。LP/SLSQP数值失败时回退到有效候选，始终重新检查原始指标。
3. **按需新增成员。** 只有配置了新增fit预算时才继续。每次只拟合一个有效模型族，权重计算复用已有预测。停滞会切换模型族，deep可维护少量划分锚点；不平均摊给64个划分。
4. **单独复核。** 默认对最终实际启用的成员做最多4个固定划分复核，仅报告，不据此换掉高分冠军。复核并非独立外部测试。
5. **分别保存。** 实际获分快照与全部允许开发记录重拟合分别保存；默认运行获分快照。

基线合格时，新结果必须保持开发MAPE/R²均不差且满足同样训练门槛才可替换。若原V3冠军不满足新增训练门槛，报告会明确显示；原参考仍保存，不能承诺所有指标无条件不退步。

## 模式与菜单

| V5模式 | 行为 |
| --- | --- |
| `goal_first`（默认） | V3基线保留，开发达标优先；跨划分复核只报告 |
| `balanced` | 在主开发目标和固定跨划分复核之间作明确权衡，保留原参考 |
| `robust` | 在候选库固定的跨划分预测上优化融合，以跨划分开发成绩作为该模式的开发成绩 |

`V5_GOAL_FIRST.bat`、`V5_BALANCED.bat`、`V5_ROBUST.bat`可快捷选择。V4原有random/global/per_split/hybrid仍保留，没有把它们改名冒充V5。

`MODE_MENU`可以切换专家开关、训练门槛、融合、部署范围、固定外层留出、复核、发布策略、基线结束方式、新增fit预算及总fit/秒数预算。版本及关键语义不同的保存模型分别登记；尚无对应模型会提示先训练，不自动借用另一模式。

V4每折门槛范围和划分覆盖策略仍在V4中配置；V5主目标是对应训练/开发对，跨划分成绩另报。`balanced/robust`即使关闭复核开关，也仍需要执行用于选择的复核。

## standard / quick / deep预算

| 配置入口 | V5预算 |
| --- | --- |
| `APPLY_V5.bat` | 新配置默认V3基线300轮，新增成员fit为0，复核另计 |
| `APPLY_V5_QUICK.bat` | V3基线40轮，新增成员fit为0 |
| `APPLY_V5_DEEP.bat` | V3基线300轮；总成员fit上限5000（包括基线、增强、复核及导出），30分钟时间预算，最多3个划分锚点 |

deep不是5000次六模型×多折配置循环。总fit上限会扣除已经使用的fit，并保留完整导出的余量，实际可能提前结束；原V2/V3的5000配置试验模式仍可单独选择。任何预算增加都不保证真实数据达到目标。

默认基线必须完整执行300轮；若选“目标达标后停止基线”或时间预算先到，报告会给出实际完成数，不能称为完整300轮复现。基线完成且训练/开发达标后，默认不继续盲跑新增成员；可以启用“达标后继续”。`robust`不以单划分达标作为新增阶段的停止依据。

## 配置位置

`config/price_optuna_v5.json`是离线包现场配置；源码默认模板位于`automl_pipeline/configs/price_optuna_v5.json`。

| 项 | 含义 |
| --- | --- |
| `search.n_trials` | V3基线配置试验轮数，默认300 |
| `search.timeout_seconds` | 时间预算，null不限；完成当前fit及可靠保存后停止，基线恢复会扣除已用搜索时间 |
| `v5.baseline.reference_dir` | 可选已有V3构建目录；表格摘要、处理/评分/采样设置和重放成绩需核验，通过后可零新增fit复用 |
| `v5.baseline.auto_reference` | 离线输入检查可尝试当前保存V3；不合格或不一致则重新运行基线 |
| `v5.baseline.finish` | `fixed_budget`完整基线，或`targets_met`训练/开发达标后可停 |
| `v5.train_gate` | `hard/soft/off`、训练MAPE/R²门槛及软惩罚 |
| `v5.enhancement.max_new_fits` | 新成员拟合上限，独立于基线试验轮数 |
| `v5.enhancement.families` | 可选模型族，保留原六类 |
| `v5.enhancement.pool_size` | 每划分候选库上限；原基线成员固定保留 |
| `v5.enhancement.patience / split_anchors` | 停滞调度及最多划分锚点数 |
| `v5.enhancement.continue_after_targets` | 达标后是否继续新增成员 |
| `v5.budget.max_member_fits` | 总实际成员fit上限，null不限；需至少预留`6*n_trials+12`确保基线不被fit上限截断 |
| `v5.fusion` | 是否融合、是否保护合格基线、数值求解迭代上限 |
| `v5.audit` | 是否复核、划分数、验证条数、成员上限和balanced权衡；不截断启用权重冒充完整复核 |
| `v5.evaluation` | `development`或`locked_holdout`、外层ID/比例/种子 |
| `v5.persistence` | 启用、恢复、目录及检查点间隔 |
| `v5.publish.policy` | 未达标允许标记试用草稿，或达标才更新运行版本 |
| `deployment.model_scope` | 默认`selected_split`，可切`full_data` |

固定外层留出至少需要6条并声明全部属性类型。外层价格不参与选参、融合、训练门槛或最终重拟合。V3兼容基线保留原划分行为；没有把它的开发分数声称为独立精度。

## 保存与恢复

基线按完成候选追加记录，保存采样状态、已完成试验和搜索冠军；新增成员阶段保存候选库、权重、采样状态及预算计数。采用内容摘要和原子元数据提交，恢复前校验数据、设置、代码和环境；不一致不复用旧成绩。

V3基线恢复后预测缓存冷启动，可能增加少量重新拟合，但参数采样和选择能继续原进程状态。已测试分别在NSGA和TPE中断后恢复，完整试验参数及成绩与未中断运行一致。

基线已完成时可以复用检查点而不重跑300轮；增大新增fit预算可以在原候选库上继续。报告区分累计fit与本次新fit。没有原输入表仍可START/EXPORT保存模型；继续训练仍需对应原表。

检查点默认放在包内`state/v5`，与正式保存模型分离；EXPORT包含模型与环境，不带原输入表或整个训练检查点目录。复核/外层成绩、获分快照成绩、全量重拟合成绩不能互相套用。

本版本的虚拟样本和自动化检查用于验证搜索、保存与软件链路，不是对真实业务精度的认证。
