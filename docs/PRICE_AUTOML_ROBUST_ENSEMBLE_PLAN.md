## 1. 当前代码的实际边界

`tools/product_price_automl.py` 已实现训练折内预处理、分组保留测试集、双指标搜索和原生服务导出，这些应保留。需要改进的部分如下：

| 当前行为 | V2 的改进 |
| --- | --- |
| 选一个获胜模型，导出一个成员且权重为 1 | 建立候选库，学习多个成员的非负权重 |
| 一个种子同时影响 KFold 和随机模型 | 分开搜索、验证划分、模型训练、bootstrap 的随机源 |
| 每次试验都做 3 种子×3 折 | 分阶段投入预算，对晋级候选增加验证和训练种子 |
| 固定数值补全/缩放，目标变换仅是总开关 | 在每个候选内部搜索预处理、特征变换和目标变换 |
| 仅将完全相同的输入分为同组 | 增加产品族、项目、生产批次、时间等业务验证协议 |
| 主要看平均 MAPE/R² | 同时报尾部误差、业务切片、组间波动和改进不确定性 |
| Optuna 时间预算在当前试验后检查 | 增加单次拟合超时、总预算分配、缓存与恢复 |

“调整所有设置”需要区分学习参数和评估协议。模型、预处理及权重可以搜索；测试集、业务分组及评估种子应预先固定，不能为了高分反复改变。

## 2. 方法选择

| 方法思路 | 适合本项目的部分 | 使用方式 |
| --- | --- | --- |
| Optuna 条件搜索 | 联合搜索模型、超参数、预处理和目标变换 | 保留 3.6.0；扩大版本受控的搜索空间 |
| FLAML 的成本感知思路 | 将预算分配给有改进希望且成本合理的候选 | 借鉴预算分配和逐步增加资源，先不引入新运行依赖 |
| Caruana Ensemble Selection | 在已缓存预测上快速挑选互补模型 | 作为快速融合方案与权重优化的初始化 |
| 非负、正则化的 OOF 融合 | 直接优化百分比误差与平方误差，控制权重波动 | 作为主要权重学习方案之一，与简单融合共同验证 |
| 非线性 Stacking | 可表达模型在不同场景的优势 | 留作样本充足时的可选扩展，初版使用可直接导出的全局权重 |

这是一项针对兼容约束的工程选择，不能从论文成绩直接推断本项目上的精度。FLAML 的参考是资源预算设计，Caruana 的参考是模型库与逐步集成；最终效果由本项目的验证结果决定。

## 3. 验证协议先于搜索

1. 固定一份最终保留测试集；完成所有模型、超参数、种子策略、融合方法和权重选择后再评估。再次修改方案须记录对同一测试集的使用历史。
2. 完全重复配置始终同组。真实数据若有产品族、项目、厂家、批次或时间关系，使用业务分组或时间阻断；按实际上线场景选择协议。组和时间字段默认不参与价格特征。
3. 所有候选使用相同验证折。特征变换、补全、缩放、特征筛选，以及需要学习的工程关系，均在相应训练折内拟合。
4. 普通搜索可使用开发集 OOF。正式审核的外层验证必须重跑整个内部选择过程，包含模型/参数/预处理选择和权重学习；把全局选好的模型拿到外层再验证会低估选择偏差。
5. 在一个外层训练集内部，生成内部 OOF 预测并学习权重，再将基模型重训于该外层训练集，预测外层验证集。外层验证标签不参与权重学习。
6. 时间任务使用前向切分。sklearn 0.24 没有新版 `StratifiedGroupKFold`；需要按版本实现并测试相应组切分器，不直接复制新版本 API。

同一组开发集 OOF 用来调模型和调权重时，其分数是调优分数。需要外层完整验证或最终保留集评估来衡量泛化。[sklearn 嵌套验证说明](https://scikit-learn.org/0.20/auto_examples/model_selection/plot_nested_cross_validation_iris.html)

## 4. 随机性：扩大覆盖，分开作用

| 随机源 | 用途 | 是否作为“挑最好分数”的参数 |
| --- | --- | --- |
| 搜索种子 | 保证 Optuna 搜索顺序可复现 | 否 |
| 验证划分种子 | 覆盖不同训练/验证分组 | 否；预先生成并固定 |
| 估计器训练种子 | 森林、随机提升等模型的训练随机性 | 用于平均和稳定性检查 |
| 重采样种子 | 分组 bootstrap 的改进区间 | 否 |

建议初筛用一个固定验证重复；晋级候选从 3 次重复开始，按结果波动继续到 5～10 次。进一步设计将随机模型的训练种子改为可复现的流，按 4→8→16 个实例逐级平均，仅在深入档位且预算允许时扩展到32个。具体数量由实测预测波动、边际收益和成本决定，达到上限仍不稳定时如实报告。确定性的 Ridge、Lasso、Huber 等模型只需一个训练实例；更换训练种子不会生成新的独立模型。

每个随机模型配置先在训练种子内平均，形成一个配置候选，再在配置层学习集成权重。这样可以避免一个模型族因为实例数量多而获得额外投票权。导出时将配置权重分配到其 seed 成员，记录各层权重。

## 5. 搜索完整流水线

模型候选以现有版本可用的算法为主：Ridge、Lasso、ElasticNet、BayesianRidge、Huber、SVR、KernelRidge、KNN、RandomForest、ExtraTrees、GBDT。HistGradientBoosting 作为第 12 类受控候选：0.24 中需 experimental 启用，训练和重新加载都通过目标环境测试后再开启。高斯过程可作为小样本限定扩展。

| 搜索层 | 可配置选项 | 约束 |
| --- | --- | --- |
| 数值缺失 | 中位数/均值、缺失指示器 | 所有统计只来自训练折 |
| 数值缩放 | 无/StandardScaler/RobustScaler | 按模型族启用；树模型不重复探索无意义缩放 |
| 数值变换 | 原值/Yeo-Johnson、指定属性的对数 | 按值域、单位和模型族筛选 |
| 分类编码 | 独热、稀有类别合并 | 0.24 需自己实现稀有值合并；未知值策略单独检查 |
| 目标变换 | 原价格/log、可选 Yeo-Johnson | 使用 `TransformedTargetRegressor`，逐模型还原价格 |
| 工程特征 | 数值交互、温度跨度、经确认的物理比值 | 增加数量上限；防止零分母和目标/结果字段泄漏 |
| 特征筛选 | 关闭/低方差/受控监督筛选 | 在训练折内执行，不改变业务属性代号 |
| 模型参数 | 每个模型族的强度、深度、核参数等 | 使用 0.24 参数名和支持值，保存实际有效参数 |
| 拟合样本权重 | 关闭/有上限的相对价格权重 | 仅对支持 `sample_weight` 的模型开放；原始验证指标不改 |
| 集成 | 候选规模、方法、正则、尾部惩罚、seed 数量 | 权重非负、总和为 1，验证复杂度带来的收益 |

不要无界组合所有选项。采用条件搜索：缩放重点面向线性/距离模型，交互项重点面向正则化线性模型，树模型重点搜索深度/叶子/采样。每种模型先获得少量预算，再按改进潜力增加。

GBDT 0.24 的损失名使用 `ls`、`lad`、`huber`；HistGBDT 0.24 使用 `least_squares`、`least_absolute_deviation`。不能直接使用新版本的参数名。模型库的每个分支必须实际拟合并重新加载后，才算支持。

## 6. 分阶段搜索与缓存

```text
固定数据身份、分组、测试集和评估协议
  → 低成本初筛：模型族＋条件预处理＋粗参数
  → 晋级验证：细参数＋更多折/重复＋训练种子平均
  → 缓存开发集 OOF 预测与误差相关性
  → 互补候选筛选＋多种融合方法及权重优化
  → 外层完整审核（按档位）＋一次最终保留集评估
  → 全量重训＋原生加权模型包＋三环节流水线
```

OOF 缓存键包含数据摘要、字段顺序、分组协议、验证折、预处理、模型有效参数、估计器种子、代码和依赖版本。改权重、候选子集或评分参数时复用预测；改模型或特征时只重训受影响候选。

Optuna 3.x 的多目标 `Trial.report()`/`should_prune()` 不能直接套用普通单目标剪枝。保留 MAPE/R² 双目标时，使用搜索器之外的阶段晋级与预算控制；另一可选模式是明确的标量调优目标加单目标剪枝，并完整记录两个指标。[Optuna 限制说明](https://optuna.readthedocs.io/en/v3.5.1/reference/generated/optuna.trial.Trial.html)

逐折统计改善、成本和剩余预算；早停对照候选必须使用一致的折序。总时间、每个拟合任务、内存和最终成员数量都有上限。Windows 工作进程由父进程管理；超时只停止该任务创建的进程，保留已完成结果。默认为一个搜索进程、模型 `n_jobs=1`，避免旧机器过度并行。

预算分配可借鉴成本感知 AutoML，而非对所有候选投入相同资源。[FLAML 原论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2021/03/MLSys21FLAML.pdf)

## 7. 权重学习是单独的低成本阶段

令 P 是开发集 OOF 预测矩阵，每一列是完整候选流水线在原价格空间的预测。融合为：

\[
\widehat y_i=\sum_j w_jP_{ij},\qquad w_j\ge0,\quad\sum_jw_j=1.
\]

候选库用误差质量、误差相关性和计算成本共同筛选。预测相似但差的候选剔除；同一族的高度相关候选可合并或限额。低相关本身不能让一个差模型进入集成。

对固定 P，可用 SciPy 1.5.4 的 SLSQP 优化低维权重，例如：

\[
L(w)=\alpha\operatorname{MAPE}_{relative}(Pw)
+(1-\alpha)\frac{\|y-Pw\|_2^2}{\sum_i(y_i-\bar y)^2}
+\lambda\|w-w_0\|_2^2
+\eta\operatorname{CVaR}_{0.9}(APE).
\]

平方误差归一项等于 `1-R²`；在固定样本上可直接优化。MAPE 与平方误差对线性权重是凸目标，正则使权重更稳定。CVaR 若启用，应以辅助阈值变量实现；单纯使用分位数不等价于 CVaR。优化器失败时必须检查可行性并回到已验证的简单权重。

纯 MAPE 可转为线性规划；SciPy 1.5.4 的 `linprog` 使用其已有的 `interior-point` 等方法，不能用后来加入的 `highs`。

同时验证三种融合：Top-K 等权或收缩权重、Caruana 逐步集成、非负正则化权重。权重方法及 alpha/正则强度也只能用内部验证选择。逐步集成直接在已缓存的预测上工作，适合作为低成本候选。[Ensemble Selection 原论文](https://www.cs.cornell.edu/~caruana/ctp/ct.papers/caruana.icml04.icdm06long.pdf)

**稀疏控制须真实有效。** 非负且总和为 1 时，`||w||₁` 恒为 1，不能靠它得到稀疏权重。通过互补候选筛选、逐步集成和成员数量上限控制规模，并重新验证删除小权重的影响。

默认输出加权集成，允许差模型权重归零。最佳单模型始终保留作对照；有效成员不足或融合未通过验收时，按配置明确降级，不强行给弱模型分配正权重。常规目标是 2～6 个配置候选，seed 实例数量另计。

## 8. 鲁棒性与优秀表现的验收含义

除平均 MAPE/R²，报告 MdAPE、P90/P95 APE、WAPE、各产品族/环境/功能切片的误差，以及组间与重复间波动。真实价格为零/负数时须先解决业务定义；小价格的 MAPE 高敏感性需要单独诊断，不能偷偷改变分母或删掉验证样本来提高分数。

在相同记录上对集成与基线做配对分组 bootstrap，报告改善区间。若区间含 0，则不宣称精度改善。固定模型的 bootstrap 只衡量条件数据不确定性；完整选择不确定性仍要依靠外层重跑、重复验证和后续批次。

对输入越界、未知类别、缺失、模型间分歧和极端环境给出明确状态。OOF 残差区间与模型分歧是诊断，不自动具有 95%覆盖率。若需要有统计含义的区间，应另留校准数据并检查实际覆盖率；时间漂移和组数据下也须检查适用假设。

推荐系统会主动搜索新组合，可能放大价格模型在训练范围外的误差。建议把价格范围/分歧诊断传给推荐评分，必要时按价格上界做预算判断；效能耦合约束仍由效能服务负责，价格的低点不能替代工程可行性。

## 13. 进一步设计：随机性、差模型与专家知识共同处理

### 13.1 种子覆盖不能替代模型偏差诊断

种子数值本身没有好坏顺序；更大的整数或更远的整数间距不会提高质量。用 NumPy 1.19.5 已支持的 `SeedSequence` 生成可复现的估计器种子流，验证划分另用预先冻结的随机源。种子应服务于稳定性评估与平均，而不以最高验证分数挑选“幸运种子”。

晋级的随机模型配置按4→8→16逐步增加训练实例。每次追加只计算新的拟合任务，并记录配置平均预测的变化、重复折误差的波动和耗时。连续两轮预测变化很小且平均验证收益停滞时停止追加；这是预算启发式规则，不是正式置信保证。整个追加与停止策略必须在外层训练部分重跑，外层验证标签不得决定增加哪几个种子。

如果不同种子仍然普遍差，检查同方向残差、遗漏属性、产品族/时间漂移、单位、标注和样本覆盖，再扩大工程特征、目标变换或模型族。若真实价格200，而所有候选预测在80～100之间，非负且总和为1的融合仍在80～100之间；增加种子和优化权重都无法消除这类共同偏差。

### 13.2 差模型按有效贡献处理，搜索也应考虑最终集成

- 训练异常、非有限输出、价格单位/逆变换错误和不合法价格属于硬淘汰；专家高权重不能绕过这些检查。
- 单模型误差较大但残差互补的候选，可限额参与内部融合，依据加入后在内层选择中的平均、尾部和场景误差变化决定是否保留，由外层验证审核完整选择策略。低相关仅是线索；没有可靠边际收益就归零或删除。
- 先在同一配置内平均种子，再学习配置和模型族的权重。同一模型族有更多配置/种子，不应自动得到更多投票。
- AutoML第二阶段按“对当前集成的边际收益/成本”分配候选搜索资源，交替优化候选参数和融合权重。每个模型单独最优的参数组合，未必是融合后的最优组合。
- 用折内生成的当前集成 OOF 残差诊断不足，并定向产生新候选。若训练残差修正器，残差目标也须在相应训练折中交叉拟合；不得将全数据残差或外层验证标签带入训练。
- 用价格常量基线、最佳单模型和简单融合对照。所有候选与融合都未过业务目标时，产物标记未达标，输出缺口与下一步数据/模型改进，不能把合法权重当作准确预测。

### 13.3 模型权重、属性权重和工程约束分别绑定

| 专家输入 | 实际意义 | 接入位置 |
| --- | --- | --- |
| “森林族占40%，线性族占60%” | 模型融合比例 | 对模型族总权重的先验或明确上下界，族内再分配置/种子 |
| “性能0.5、功能0.3、环境0.2” | 效能/偏好取舍 | 归一化效用及其分组权重；用专家评分、成品偏好比较或实际效能标注校准 |
| “载荷增大价格不应下降” | 条件价格方向 | 价格模型的单调约束或可解释成本模型，须注明保持哪些其他属性不变 |
| “推力、速度、温度须满足某关系” | 工程关系/可行域 | 工程特征、效能耦合规则和推荐生成约束，不能只作为融合比例 |

当前效能试用构建器已能接受英文属性代号绑定的属性权重和偏好方向；价格专家融合本节仅有独立原型。专家的属性重要性不能直接当作带单位的价格回归系数，价格标签也不能代替效能标签学习“好不好”。

### 13.4 模型专家权重：软先验与误差预算两种模式

记专家给出的完整模型/模型族先验为p，置信或信任系数为c，实际融合权重为w。软先验模式使用：

\[
\min_{w\in\Delta} L_{OOF}(w)+\lambda\sum_jc_j(w_j-p_j)^2,
\qquad \Delta=\{w\ge0,\ \sum_jw_j=1\}.
\]

lambda控制接近专家意见的程度，必须包含lambda=0的纯数据对照，通过内层验证选择。数据稀少时可以更多收缩到合理先验；证据充足且先验冲突时允许明显偏离。多位专家记录各自范围、置信、来源和版本；完整先验可按信任加权汇总，部分先验只对已给出的分量计算惩罚。专家分歧须保留解释，头衔不等于统计置信度。

对于希望明确约束精度代价的情况，推荐性能预算模式。先求纯数据权重w_d，再求在质量预算内最接近专家先验的权重：

\[
\begin{aligned}
\min_w\;&\sum_jc_j(w_j-p_j)^2\\
\text{s.t.}\;&w\in\Delta,\quad l\le w\le u,\\
&MAPE_{OOF}(w)\le MAPE_{OOF}(w_d)+\varepsilon_M,\\
&R^2_{OOF}(w)\ge R^2_{OOF}(w_d)-\varepsilon_R.
\end{aligned}
\]

epsilon_M以**MAPE百分点**配置；例如2.0%最多增加0.1个百分点，允许上限为2.1%。epsilon_R是R²的绝对降幅。这给出可检验的开发集折外性能边界；外层验证与保留集仍须独立验收，不能保证未来样本一定满足同一边界。参考权重不使用专家上下界，否则强制劣质模型会先降低比较基线，掩盖代价。

未指定的权重不等于0；软先验0不等于禁止该模型。禁止必须显式设置上界0。直接采用含0的KL先验会意外排除新候选，初版用上述L2偏离避免这种含义。部分权重使用整个融合的绝对份额；不要未经声明就把部分份额重新归一化成100%。

明确硬性要求时先检查非负、单位、上下界及simplex可行性。固定差模型80%且误差预算很小可能无解；报告冲突和各约束代价，不擅自改变硬性要求。数值优化未收敛只代表没有找到可接受的解，不能据此声称已数学证明无解。纯数据回退只有在仍满足明确硬约束时才可采用。

### 13.5 可解释价格结构与场景融合

需要解释属性如何影响价格时，可增加候选“工程成本基准＋交叉拟合残差修正”：

\[
\widehat p(x)=p_{engineering}(x;\theta)+\sum_jw_j\delta_j(x).
\]

工程部分使用带单位、方向和范围约束的可解释贡献；残差模型弥补非线性与遗漏关系。theta若由价格数据估计，也须在折内拟合。把该结构作为一种候选，与完整直接预测的候选独立比较；基准不能重复加进总价。

sklearn0.24.2已支持实验性的HistGradientBoosting单调约束，可用于经工程确认的价格方向。[0.24官方示例](https://scikit-learn.org/0.24/auto_examples/ensemble/plot_monotonic_constraints.html) 若必须保证整体单调，所有价格分量与变换须保持对应方向，并使用常数非负融合权重；自由残差模型或随输入变化的权重可能破坏这一保证。仅抽查若干输入不等于结构保证。

当真实数据足够时，可使用少数业务场景的局部权重，并收缩到全局专家/数据权重。样本少的场景复用全局结果；不能用未知的真实价格作为选择权重的条件。层次stacking研究支持按输入变化并进行部分共享的思路；本项目的兼容实现拟用简单受约束优化与收缩，论文中的贝叶斯预测密度/MCMC方法不是本项目已经实现的价格MAPE算法。[Hierarchical Stacking原论文](https://sites.stat.columbia.edu/gelman/research/unpublished/2101.08954.pdf)

场景融合与整体单调要求应分别验证；当前常数权重原生包不能直接表达输入变化的权重。最差业务场景误差惩罚仅约束已观测、样本足够的场景，不保证未知环境下的最坏误差。

中文解释输出至少包括：专家原权重、最终权重、偏离、信任系数、改变理由、各成员预测价与加权贡献、工程部分贡献、残差修正，以及越界/分歧状态。成员加权贡献解释模型组合，不能当作属性重要性或因果贡献。
