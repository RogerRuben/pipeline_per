## 1. 审查结论

**P0 的架构基线可以接受，建议直接开展 P1。P0 尚未完成实际模型/运行环境验收。**

已存在：上游推荐与 AutoML 源码、价格 HTTP 服务、SQLite、Portal；P0 架构与字段契约、13 个拟议深度分析 API 路径、旧页面参考源码与路由清单、初始构建配置、审计记录。

关键证据与限制：
- `docs/audit/P0_validation.json` 声明 **174 项结构与来源检查通过**，不代表运行时测试。
- `docs/audit/upstream_compatibility_test.json` 声明 **18 项中 16 项通过、1 项失败、1 项错误**；环境 Python 3.12.8 缺 Optuna，存在子进程超时的连锁问题，需在目标 Python 3.8 环境重跑，不应视为 Win7 验收。
- `config/build_profile.json` 中 `price_engine=optuna_v3` 是声明而非执行器，原有 AutoML CLI 默认 V7。需要在实际构建入口强制使用 profile 的引擎选择。
- 实际产品 `input/products.xlsx` 和正式 V3 模型未选定；仓库现有虚拟示例不能当作正式模型兼容或精度证据。
- 参考深度分析旧后端读旧 pickle/CSV；新页面须移除在线路径的这些依赖。参考 `index.html` 包含静态中文字段和默认参数，迁移必须改为发布产品与模型 Schema 动态驱动。
- 现有 `app/server.py` 中 `price_workbench_predict()` 的 gateway 分支可借鉴，但存在无 gateway 时的本地模型回退；深度页面 **必须强制 HTTP-only**。
- `app/store.py` 的 `sync_model_schema()` 是可写操作，深度分析只复用 `canonical_business_parameters()` 与 `runtime_parameters()` 等读取/映射流程，不能由分析请求触发管理副作用。
- `services/price_service/app.py` 已提供 `/api/v1/schema`、`/api/v1/predict`、`/api/v1/predict/batch`、`/health`，批量上游上限为 1000；新深度接口按 P0 草案暂限 100。

## 2. 下一阶段边界

**P1 的目标**：通过推荐系统同源 Portal 打开 `/price/deep`，完成 `index.html` 主界面的产品选择、动态参数、单价预测、批量服务适配、价格校正占位、导出和必要的机理解释占位，且与推荐系统使用同一产品发布版本及价格 HTTP 服务。

**不属于 P1**：真正的 EXE（P4）、泵 V13 算法改造/正式冻结包（P5）、正式 LLM 机理解释、可加属性完整规则与混合变化定价（P3）、完整 Top10/情景/模型评价（P2）。不修改既有 AutoML V3 算法、推荐排序、SQLite 表结构，除非提前提交有证据的变更方案。

4. 定义 `release_id`、`product_id`、`product_code`、`model_version`、`price_model_sha256`、`price_unit` 的来源、验证时机和冲突行为；规范 `400/401/403/409/422/503/504`。

### P1-1 · 最小端到端价格通路（首个必须优先完成的可运行中间产物）

1. 建立 `app/deep_price/` 中的 `schema/provider`、`gateway` 与 `analysis` 适配层（名称可根据实际工程约定修改）。
2. 产品列表来自当前**激活的发布版本**及业务历史，不扫描旧 `样本1.csv`、不按旧页面 25 个固定中文列定位。
3. 业务字段通过 `Store.canonical_business_parameters()` → `Store.runtime_parameters()` **恰好编码一次**，按当前模型 Schema 过滤传入字段；前端不自做类别到数值的编码。
4. 后端强制价格 HTTP 网关；新增纯价格批量方法，不连带调用效能服务。用产品和模型的服务器端快照构建版本令牌。
5. 先挂 `/api/deep-price/v1/schema`、`/products`、`/products/{product_id}`、`/predict`、`/predict/batch`；暂不动完整 UI。
6. 批量输入保持顺序，限 100 条、总预算约 30 秒（以规范为准），启动前及完成后核验激活发布/模型身份，发现变化整批返回 `409 version_conflict`，不展示混版结果。

**交付**：可在临时数据库 + 测试模型上调用的真实 HTTP 接口和自动化对照测试。

**验收门槛**：相同业务输入通过推荐系统/现有简易价格工作台/深度接口获得同一模型下的一致原始预测（预设浮点容差）；模型服务断开返回 503、不回退旧 pickle；枚举和缺失语义正确；无分析引起的 registry、发布表、业务记录写入。

### P1-2 · index.html 主界面迁移

1. 以 `references/deep_price/templates/index.html` 为视觉和行为基准，迁移到 `app/static/deep_price/`；保留布局、分组标签、产品选择、编辑参数、预测结果、雷达图与对比图等可复原交互。
2. 改用 Schema 动态生成属性控件；显示中文标签、单位和业务可选值，内部使用稳定 `field_id`；切换产品时清理旧预测与缓存。
3. 添加 `/price/deep` 同源路由，复用 Portal 登录、会话、静态资源和既有 CSRF/来源校验策略。待端到端通过后再启用 `advanced_price` 导航。
4. 模型库改为**只读摘要**；不存在上传、激活、替换与回滚按钮。机理分析/LLM 显示 `not_configured`，不静默调用公网服务。
5. 保留引用中的 ECharts 作为可用离线资源，但发行前确认许可证。

**交付**：可浏览的深度价格分析主页面、视觉前后对照截图、浏览器回归测试。

**验收门槛**：真实产品与中文属性回填正确；数值、整数、布尔、枚举、缺失输入可编辑；预测结果和图表正常；刷新和未登录场景正确；无旧静态字段强制绑定。

### P1-3 · 校正、导出和故障状态

1. 把原预测价格与年份/PPI/批量校正价分开展示。只有获确认的价格指数/基年/数量弹性规则才计算；否则明确 `not_configured`，不复制旧常量当正式业务规则。
2. 服务端为每次计算分配 `result_id`，绑定会话与产品/模型版本，30 分钟有效；导出 CSV/TXT 只读取服务器侧结果，带来源、单位、模型摘要、规则版本；对公式型 CSV 内容做安全转义。
3. 处理输入非法、模型服务超时、模型版本切换、登录失效、结果过期、批量过大等可见错误，不展示虚假成功状态。
4. 额外增加部署去原始 Excel 测试：删除/移动构建期源表后，已发布服务仍能预测，启动不得主动重训。

**交付**：一轮完整的使用链路录屏/截图、错误行为测试报告、导出样本。

**验收门槛**：所有分析操作不产生产品、模型或业务持久化写入；导出不能用前端伪造价格；未配置校正不得产生正式价格。

## 4. 验收总门槛（P1 Done）

| 验收项 | 要求 |
|---|---|
| 服务一致性 | 推荐、简易价格、深度价格同产品/输入/模型得到相同原始预测 |
| 字段契约 | 读取当前激活 release，中文展示/英文 ID/单位/枚举映射一次，跨产品切换正确 |
| 模型约束 | HTTP-only；模型缺失/故障返回不可用，绝不加载旧 pickle 兜底 |
| 版本控制 | 单/批请求携带可追溯版本；分析中切换模型或发布版本报告 409 |
| 数据安全 | 分析请求不调用注册表同步/管理员写 API；在隔离 SQLite 检验关键表记录内容/版本均未变化 |
| 运行安全 | 同源认证、访问控制、导出隔离、防 CSV 公式注入，静态资源不依赖网络 |
| 页面复原 | `index.html` 的主要输入、产品选择、价格结果、图表、状态、导出可使用；未完成功能显式占位 |
| 基线不回退 | 推荐和已有价格服务回归通过；原 Excel 移出仍可使用已发布模型 |
| 证据 | 每项测试记录命令、环境、源码 SHA、模型 SHA、结果和截图 |

**双层验收**：允许基于明确标记的虚拟数据通过 P1 开发功能验收；正式 V3 成品模型、真实 `products.xlsx` 和 Win7 实机验证各自是独立的交付门槛，不能用虚拟数据通过替代。
