# 4—7条成品记录配置补丁

将补丁完整覆盖到现有V2/V3离线包根目录，运行`APPLY_V2_V3.bat`，再`CHECK_INPUT.bat`、`RETRAIN.bat`。环境无需重装。原模型、版本选择、专家评分、搜索预算及目标均保留；START继续只加载保存模型。

两版分别编辑`config/price_optuna_v2.json`和`config/price_optuna_v3.json`。安装后会补全以下设置，保留同一对象中的其他配置项：

```json
{
  "input": {
    "min_samples": 4
  },
  "validation": {
    "test_size": 0.2,
    "auto_adjust_test_size": true
  }
}
```

`min_samples`是有效价格记录的最低数量，允许设置为4或更大的整数。只在config中改数字无法修改旧程序中写死的8条限制，必须先覆盖本补丁。低于4条不能同时保留至少2条训练与2条R方验证，本补丁不接受1—3条。

| 有效记录 | 默认训练 | 默认验证 | 实际验证比例 |
| --- | ---: | ---: | ---: |
| 4 | 2 | 2 | 50% |
| 5 | 3 | 2 | 40% |
| 6 | 4 | 2 | 20%（记录数向上取整为2） |
| 7 | 5 | 2 | 20%（记录数向上取整为2） |

设置`auto_adjust_test_size=false`可严格使用自定义比例，不满足训练/验证各2条时会在训练前报出具体原因。默认自动模式只调整不可行划分，16条、20%等原本可行的划分保持原算法结果。可选异常过滤后仍会重新检查有效数量。

`price/validation_split.json`及`training_report.json`记录原比例、实际比例、训练/验证条数和是否自动调整。`requested_config.json`保留原设置，`effective_config.json`记录实际训练设置。保存、重载、导出及V2/V3切换流程保持原用法。

4—7条尤其是40个左右属性时，开发分数对划分很敏感。本补丁支持少量数据试用，不把搜索开发成绩当作独立业务精度证明。
