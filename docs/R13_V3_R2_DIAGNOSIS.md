# V3 的 R² 说明

这次没有改搜索公式，也没有把算不出来的 R² 写成 0。

## 两种“0”不是一回事

价格完全相同，或者有效记录少于 2 条时，R² 没有定义。程序记为 `r2 = null`、`r2_status = undefined`，搜索直接跳过这个候选，不把它当成 0 分。

价格有变化，而预测接近全体均价时，R² 可以真实等于 0。这表示模型没有比“猜平均值”更好，是预测表现，不是计算错误。均价预测在一组 10、20、30 上得到的就是这种 0，同时 MAE 大于 0。

所以，先前看到的 R²=0 仍可能是当时模型的真实成绩。不能因为现在挡住了“不可定义”，就认为原来的 0 已经消失。

## 搜索实际在优化什么

V3 仍然只把 R²（越大越好）和 MAPE（越小越好）交给 Optuna。MAE、RMSE 会写进同一份指标，但不参与择优，也没有加入“四项都不许变差”的约束。

划分种子和模型参数是一起搜的。报告里的验证 R² 是被搜过的那一档开发成绩，不是一份事先锁死、没有参与选择的独立测试。

## 还缺什么才能回答甲方那次的 0

需要甲方当时的成品表，用固定验证集或交叉验证再算一遍四个指标。本次工作区没有这份表，因此不能判定那次 0 是程序问题还是模型拟合问题。现场验收前不要把模拟样本上的分数写成甲方结果。
