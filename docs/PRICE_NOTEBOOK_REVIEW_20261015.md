## Notebook实际做了什么

1. 先用IsolationForest筛除样本，按价格分位数建立两个分层。
2. 用REF_SEED=0得到80%训练、20%验证；训练特征做MinMax归一化，训练价格取自然对数。
3. 先调一次参数。Lasso和Ridge按参考验证集的原价格误差选择alpha；SVR、GBDT、ExtraTrees在参考训练集上做10折调参；专家树使用留一法。后面的种子循环不重复完整网格。
4. 从1—10000抽取300个划分种子。每个种子重新分层划分、重新拟合训练集归一化器，并训练全部六个模型。GBDT和ExtraTrees的模型random_state仍固定为0。
5. 六个模型是Lasso、Ridge、SVR、GBDT、ExtraTrees、ExpertWeightedTreeRegressor。最后一项代码中命名rf，但实际是一棵自定义专家分裂树，并非标准RandomForestRegressor。XGBoost未进入这份文件的六模型融合。
6. 每轮都在该轮验证样本上计算六个模型误差与联合预测，寻找R²>0.9、MAPE<10%的划分。保存的执行结果找到10个候选，最终取第一个达标种子9300，并非取R²最高的候选。

| Ridge | alpha=0.1 |
| SVR | kernel=linear，C=1，epsilon=0.01，gamma=0.01 |
| GBDT | n_estimators=300，max_depth=3，min_samples_split=2，learning_rate=0.1，subsample=0.7 |
| ExtraTrees | n_estimators=300，max_depth=10，min_samples_split=4 |
| 专家树 | max_depth=5，min_samples_leaf=1，lambda_expert=0.8，min_gain_split=0.1 |

## 当前版本的实质偏离

### 1. 搜索的种子不是同一种东西

Notebook的_prep(seed)把seed传给train_test_split。换seed会改变哪些成品参加训练、哪些成品参加验证，也改变训练样本顺序。

R4.3的InnerSearch在初始化时就由validation.seed生成self.folds。后续oof_repeated(candidate, seed)换的是模型种子和组样本权重扰动，划分不变。种子报告的一次尝试只对应一个候选配置的完整内层CV；Notebook的一次尝试对应一个新划分下的全部六模型联合预测。因此两个“5000次”连计数口径也不同。

这是此前没有实现原思路的直接证据。增加同类扰动次数不能代替训练/验证组成搜索。

### 2. 搜索空间没有包含已经找到的解

当前R4.3继承的R4.2预设把GBDT与ExtraTrees的树数量上限都设为256，而Notebook两者的已知最佳值都是300。当前配置校验还不允许设置ExtraTrees的min_samples_split，Notebook最佳值4无法由当前AutoML配置表达。

当前预设名单没有expert_tree，开启EXPERT_COMPARE也没有把它补入。现有ExpertSplitTree与Notebook树也有差别：Notebook一条路径禁止重复使用同一特征，并支持min_gain_split；现有树不具有同样的搜索参数和路径限制。

这些是可查证的覆盖缺口，不能仅用“用了更多模型、扩大参数范围”描述为改进。

### 3. 预处理和专家先验没有对齐

Notebook固定MinMaxScaler和log(price)。当前配置只支持standard、robust、none，根本没有MinMax选项；还把identity/log、多种筛选视图放在有限预算中竞争。当前默认纯数据模式关闭专家评分，Notebook则对不同模型使用不同的评分映射：

| 模型 | Notebook的1分→5分倍率 |
|---|---|
| Lasso | 0.5→3.0；代码注释写2.5，但实际公式上限为3.0 |
| Ridge | 0.3→5.0 |
| SVR | 0.5→2.5 |
| 专家树 | 数据分裂增益×[1+lambda×(评分−1)/4] |

R4在强度1时使用0.5→2.0的统一倍率。对岭回归，特征放大相当于降低该属性原单位系数的惩罚：惩罚与倍率平方的倒数成正比。Notebook的高低评分相对惩罚比约278，现有强度1约16；默认关闭专家时没有评分差别。这会产生不同的模型，不能认为“都读取1—5分”就已兼容。

Notebook把已处理的编码列作为数值使用。兼容回放应保存这些数值语义，不应在没有对照验证时自动换成另一种编码。新业务的枚举处理可作为单独配置比较。

### 4. 评分对象和导出对象改变了

Notebook记录的是挑选出来的一次20%验证划分。R4主指标是多个外层验证误差的汇总，最终又在全量数据上重新选择和拟合。两种成绩回答的问题不同，也不对应同一个拟合对象。

完整外层审核有其用途，但不应在没有建立Notebook同条件基线时，替代用户要求的开发搜索。全量重拟合也不是原获胜模型的简单保存，不能直接继承获胜快照的验证成绩。

## 已做的两个数值实验

### 六模型融合复算

从cell40保存的6×6预测矩阵及cell42的真实价格重算，没有重新训练任何模型：

| 融合 | MAPE | R² |
|---|---:|---:|
| Notebook误差权重融合 | 9.586662% | 0.938790513 |
| 六模型等权融合 | 9.617399% | 0.938736747 |

原权重公式可化简为w_i∝1+max(e)−e_i，e为0—1口径MAPE。六项权重约为[0.164914,0.167181,0.162452,0.170378,0.166642,0.168433]，非常接近等权。复杂权重相对等权只改善约0.03074个百分点。

这个例子支持“优先保住六路预测的训练过程与互补性”，不能据此证明某种融合对用户当前16×36表普遍更优。按单模型排名提前裁掉成员，也可能丢掉联合预测时的误差互补。

### 评估函数会改掉待部署模型

cell16的new_3_indictors循环直接调用model.fit(X_cv_train, y_cv_train)。传进去的是原模型，使用的df_X、df_y是原始特征和原始价格；而前面预测使用的是归一化特征和对数价格训练。

仅提取并执行已审阅的该函数及其置信区间辅助函数，在12×3受控数据上验证：传入前后仍为同一个Ridge对象，参数已改变，同一输入的输出从约4.6—5.2变成约63.7—74.4。此实验只证明函数副作用，不检验业务精度。

前面各模型的*_complete.pkl在该评估调用之前保存；cell44保存裸lasso.pkl、ridge.pkl等则在评估调用之后，后者可能已是另一种输入空间/目标空间的模型。部分“加载预测测试”还没有重新施加专家特征倍率。

应克隆整条预测流水线做评估，并显式保存target_transform，删除“价格最大值小于50就当作log再exp”的猜测。相关工程原则见[sklearn0.24预处理一致性说明](https://scikit-learn.org/0.24/common_pitfalls.html#inconsistent-preprocessing)与[clone接口](https://scikit-learn.org/0.24/modules/generated/sklearn.base.clone.html)。这处Notebook缺陷需要修复，但不能用它解释当前R4的业务效果差，更不能代替复现有效基线。

## 下一版应如何收敛

### 第一步：建立Notebook兼容内核

保持现有双行表头、英文唯一代号、中文界面与价格/效能/推荐接口。训练内核先恢复六模型、MinMax、log价格、模型专属专家映射、专家树路径约束及完整参数。默认使用全部处理后属性，先不叠加新的筛选与复杂候选竞争。

提供参考划分调参一次→冻结参数→真正搜索划分种子→六模型联合预测的完整主流程。参考参数种子、划分种子、模型种子、样本扰动种子分别记录。兼容回放采用原评分口径；业务调参可另设3/4/5折，不能对每个外层折都重复完整AutoML后再把主要预算消耗在审核上。

专家模式与纯数据模式采用相同划分列表比较；用户提出“尝试纯数据”不等于未经对照就永久关闭已有先验。原评分保持1—5分，映射及强度在内部处理。

### 第二步：让种子搜索更有效

每个候选记录有序训练ID、有序验证ID、参数、模型种子、预处理与专家设置、六模型预测、融合权重及得分，支持中断续跑；显示实际完成的完整联合预测轮数。5000是可执行预算，达到目标或预算耗尽的原因应明确，不能把尚未跑完的上限当成完成数。

16条、20%验证意味着4条验证记录。全部可能的验证集合最多C(16,4)=1820；若恰为8+8两个价格层且各抽2条，则只有C(8,2)^2=784个。可研究均衡覆盖不同划分，而不盲目重复抽种子。GBDT在subsample<1时可能随训练行顺序而变，所以若保留原顺序，缓存键不能只用验证集合；若固定排序，则把模型随机性明确作为另一个搜索轴。上述784是有条件的例子，不是对用户真实分层的断言。

保留多个达标六模型快照供比较。跨不同划分联合多个快照时，要另用共同未见样本或一致的折外预测评价；不能把模型见过的其他候选验证点混进“测试成绩”。

### 第三步：冻结实际获胜的预测链

优先保存获胜时已经拟合的六模型、scaler、专家倍率、特征顺序和融合权重，加载后逐样本重算，并核对预测、MAPE与R²。评估函数不允许更改这些对象。

若额外导出全量重拟合模型，应作为独立版本标记，不套用获胜快照的成绩；选择服务哪个版本由明确配置控制。保留START直接载入、RETRAIN显式重训与版本回退功能。

### 第四步：用对照决定增强项

在相同输入、行清单、划分、专家条件和评分口径下，依次对比：原六模型近等权、轻度误差加权、成员淘汰、受约束权重优化、稳定性筛选、其他模型。一次只改一组机制，同时报告时间和逐记录误差。确有提升再纳入默认路径。

重复试验同一验证集来选择种子、参数和权重，得到的是开发搜索成绩。可以保留这种开发优化，但要另列未经该轮选择的复核成绩，不把两者混成业务保证；[模型选择偏差研究](https://www.jmlr.org/papers/v11/cawley10a.html)说明了这种区分的必要性。

下一版的核心验收应从“是否复现并守住已有基线、导出后是否仍是同一条预测链”开始。软件回归测试继续保留，用于检查解析、兼容、保存与启动；预测效果需要同条件的数据对照。
