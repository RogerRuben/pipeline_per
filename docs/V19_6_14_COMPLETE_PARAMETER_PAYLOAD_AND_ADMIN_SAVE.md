# V19.6.14 完整参数 JSON 与管理中心保存修复

## 修复结果

推荐系统不再把第一条历史成品记录当作全部参数定义。发给价格和效能 HTTP 服务的 `parameters` 字段现在由下列字段并集组成：

1. DataMaster/数据中心中所有已启用指标；
2. 价格服务 Schema 字段，包括价格模型专用输入；
3. 效能服务 Schema 字段。

价格和效能服务收到同一份完整 JSON，各服务自行选择需要的字段。历史成品只提供已有值，不再决定字段集合。

## 缺失值补齐顺序

字段已启用但历史记录中没有值时，依次使用：已配置模型值、Schema `default_value`、`training_mean`、可选值第一项、上下限中点、下限、布尔值 `0`。仍无法推导的字段也会保留在 JSON 中，值为 `null`，并在参数覆盖诊断中单独显示。

## 管理中心诊断

打开“数据中心 -> 模型服务”可查看：

- DataMaster 已启用字段数；
- 价格/效能 Schema 字段数；
- 最终实算 JSON 字段数；
- 不在 JSON 中的字段；
- 已在 JSON 中但值仍为空的字段。

## 保存修复

- 新建指标、标签、标签规则、耦合、约束和历史协议可自动生成编号。
- 必要的数值、启用状态、排序和规则字段由后端补默认值，避免数据库 `NOT NULL` 失败。
- 允许值必须是 JSON 数组，值映射必须是 JSON 对象，错误时显示明确中文提示。
- 数据已写入、但页面重新加载失败时，不再误报为“保存失败”。
- SQLite 约束错误统一返回 HTTP 400 和可读提示。
