# 10条、50属性价格模型的微样本修正

原始工作簿、虚拟价格生成器及11项已给定的1—5分属性评分保持原样，质量门槛仍为MAPE≤10%、R²≥0.85。不将评分变成成本系数，不注入生成价格的公式。

## 问题与修正

旧策略先将10条记录分成8条开发/2条保留，再做两层2折；外层某些训练部分仅4条，最内层仅2条。7个专家关键属性在这么少的训练记录上无法确定；对50维噪声做监督特征选择也容易挑中偶然相关变量。仅用2条且价格接近的记录计算R²，结果非常不稳定。

微样本默认改为完整嵌套**分组留一**：10组外层每次训练9组，内层每次训练8组。每次外层都重新选择参数、比较专家先验强度、扩展固定种子平均、学习融合份额。重复配置不得跨折。单条外层预测不计算R²；汇总10条真实折外预测计算MAPE和R²。

先前两条记录已反复用于诊断，不再被描述为独立保留集。微样本报告将外部测试明确记为未提供，保留旧报告作失败对照。更多数据仍支持显式`holdout_nested`模式；`auto`在不超过29个独立配置时启用分组留一。

对专家属性的岭回归增加1e-6、1e-4等弱收缩候选；包含全部属性/专家子集、无先验/半强度/全强度对照。TabPFN仍是真实候选，不能因为名字先进而强制进入最终组合；先以相同折外数据筛选，再扩展最佳神经配置的种子平均，避免在所有劣质候选上耗尽预算。

## 验收

1. 使用原始10×50工作簿和固定评分完成嵌套验证；记录每层记录身份和最小训练组数。
2. 冻结导出的模型文件摘要，再用未进入训练与选模的6个预声明随机种子生成60条独立虚拟记录，使用原有生成器，不改方程或噪声。
3. 同时比较修正版和先前失败bundle的MAPE/R²，逐种子列出结果。外部测试不参与自动选参。
4. 保存bundle后重新加载，检查单条、批量、缺失字段与HTTP预测一致；再验证推荐排序、新方案生成、属性修改后重算及中文评分页面。

`quality.hard_gate=true`时，嵌套审核不同时达到两个门槛将标记构建失败，保留诊断而禁止自动发布。交付打包默认也拒绝未达标模型，诊断用途必须显式指定`--allow-unqualified-prototype`。

运行配置：`docs/examples/price_tabpfn_micro_robust.config.json`。独立虚拟检验：`tools/verify_tabpfn_virtual_generalization.py --output 已完成的构建目录`。确切数字写入`price/training_report.json`、`virtual_generalization_report.json`和全链路验收记录。

虚拟数据通过是软件与假设下的验证，不能替代真实成品数据的独立评估。留一验证也有小样本方差，报告不作真实业务精度认证。
