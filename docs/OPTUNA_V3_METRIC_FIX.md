# V3指标与KeyError恢复补丁

完整解压覆盖现有V2/V3离线包根目录，运行`APPLY_V2_V3.bat`，再`CHECK_INPUT.bat`、`RETRAIN.bat`。环境无需更换，原评分、目标、预算和保存模型保留。START继续只运行已有保存模型。补丁累计包含最低4条的配置支持。

## 本次修复

`Nonfinite metric`表示某个候选的R²、MAPE等指标出现NaN或无穷，不能直接据此认定数据表包含空值。已用全部有限、正价格的数据复现：小训练集的属性范围较窄，线性或核模型在验证样本上外推过大，对数价格还原后导致平方误差溢出。不同搜索路径不一定触发同一候选，所以V2没看到该提示，V3仍可能遇到。

原V3把评估失败候选记成COMPLETE，并用固定惩罚分交给TPE，混入了并非实际评分的观测。现在这类候选记为FAIL，不进入TPE有效观测或最终模型选择，保留错误和划分记录后继续搜索。不将NaN替换成0，不伪造达标成绩。

TPE参数采样层若出现KeyError、浮点异常或非有限参数，会在同一参数分布内使用固定种子的独立采样恢复，并记录具体参数和原异常。只对采样器内部异常启用此恢复，不把模型数据错误混入采样器问题。

缓存评估路径若出现KeyError，会清理缓存、用原V2评估路径重算同一候选，并停用本轮余下的缓存快路径。`v3.cache_entries=0`也可以显式使用原V2评估路径；此前0只是停止存储预测，仍会运行手工缓存评估逻辑，现已修正。

## 日志与定位

- 单个候选数值不稳定时显示“跳过不稳定候选，继续搜索”，不再只显示模糊的`Nonfinite metric`。
- `price/v3_diagnostics.json`记录失败候选、验证记录行号、涉及指标、主要模型、采样恢复及缓存恢复。
- `price/all_trials.csv`、`optuna_trials.csv`区分真实完成和FAIL；失败候选无虚构R²/MAPE值。
- `training_report.json`新增`failed_trials`、`sampler_fallback_count`，缓存统计含`cache_fallbacks`。
- 如果所有候选均不可评分，仍会停止新版本导出并保留旧模型，同时保存诊断。未覆盖的代码异常继续保留原始堆栈，便于定位。

尚未取得用户机器的完整KeyError堆栈，因此不能声称已确认其具体触发位置。本补丁针对已复现的合法数据指标溢出，以及TPE/缓存路径的KeyError恢复；专项测试包含人为注入异常，完整训练验证使用真实执行的数值外推案例。

V2算法和原始模型核心保持不变。常规V3试验仍走NSGA-II后MOTPE，只有出现上述异常时启用恢复，记录真实参数、权重与成绩。
