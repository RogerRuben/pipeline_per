# Optuna V3思路审查与混合量级属性处理

## 本次能核实什么

用户提供的价格预测_Optuna_AutoML_v3.ipynb只有9个单元格，是调用入口。声明的路线为历史候选初始化NSGA-II，再围绕Pareto锚点做多目标TPE；设置NSGA_TRIALS=180、TPE_TRIALS=120、num_anchors=3。当前同目录没有它依赖的price_automl_optuna_v3.py、price_automl_core.py，Notebook也没有保存训练输出。

因此以下对V3的判断是方案级建议，不代表已经审查其实现或验证效果。现有V2流水线的代码和模型本次未修改。

## 值得借鉴的搜索机制

认可“先广泛探索，再围绕多个有希望区域精修”的方向。它适合沿用当前六模型、专家先验、对数价格和导出链，把搜索器作为可替换层，而不是重新替换整个训练内核。

需要重点核对：

1. **TPE是否继承了已评价试验。** 只把历史最佳参数排进队列，和把参数及目标值提供给TPE学习，并不相同。同一数据、特征、预处理、专家评分与验证协议下，可以复用合法试验历史；数据或评分变化时，旧参数可作为起点，旧成绩必须重算。历史数据应包含有效性、参数分布和同样的R²/MAPE单位。我们现有流水线已保存price/best_config.json及optuna_trials.csv，可作为候选来源，但需核实V3的读取格式。
2. **不能围绕种子整数大小做局部邻域。** seed=9301并不是seed=9300的相近模型。在当前分层划分的小实验中，9300的验证行是[3,5,14,1]，9301为[10,8,11,1]，9302为[4,15,12,13]。精修alpha、C、learning_rate等有连续意义；划分种子应固定在锚点或作为独立离散候选处理。
3. **锚点要有差异。** 可分别取低MAPE端、高R²端和折中点，避免三个锚点实际都挤在同一区域。分类参数与整数参数应保留合法取值，正则化等跨数量级参数适合在对数空间局部搜索。
4. **最终合并两阶段候选。** 不因TPE是第二阶段就强制采用其结果。保留原V2优选和第一阶段候选；精修没有带来合格改进时，原模型仍可选。Pareto上的不同折中点不保证每项指标都超过旧点，需要明确最终选择准则。
5. **预算不能从入口变量推断。** 需要检查120轮是所有锚点共用，还是每个锚点120轮；是否反复冷启动；最终应记录实际总轮数、基模型拟合次数、缓存命中和用时。比较V2、V3时采用相同总轮数或相同时间预算，不将150轮对300轮的差异直接归因于算法。

本机现有Optuna3.6.0支持多目标TPESampler和Study.add_trials，已通过本地接口检查。TPE有启动阶段，未继承历史的新Study并不会立即充分利用第一阶段结果。参考[Optuna3.6系列TPE说明](https://optuna.readthedocs.io/en/v3.6.2/_modules/optuna/samplers/_tpe/sampler.html)与[试验导入接口](https://optuna.readthedocs.io/en/v3.6.2/_modules/optuna/study/study.html)。实际V3是否正确使用这些机制尚不能确认。

## 更直接的效率改进

同一划分、预处理、专家映射和基模型参数不变时，改变融合权重不需要重训模型。可缓存各模型在该划分的预测，让权重搜索只做矩阵加权和指标计算。某个原本零权重的模型重新启用时，应先补训并缓存，不能把原来的零占位当作预测。

缓存应按单个模型相关参数建立，而不是把其他五个模型的无关参数也放进键。键中包含数据指纹、有序训练/验证ID、单位与编码、预处理、专家映射、模型参数和模型随机种子。全量重拟合的数据组成不同，不能借用开发划分模型冒充全量拟合。

## 1—5、80、7200应怎样处理

不同列的量级差异可用按列缩放处理。当前已交付V2在fit_ensemble中先在训练部分拟合MinMaxScaler，再分别施加模型的专家倍率；预测复用保存的scaler，不重新fit。

例如训练范围分别为：等级1—5、某性能20—80、时间1800—7200。按各列自己的范围缩放后：

| 原始记录 | 等级列 | 性能列 | 时间列 |
|---|---:|---:|---:|
| 1、20、1800 | 0 | 0 | 0 |
| 3、50、4500 | 0.5 | 0.5 | 0.5 |
| 5、80、7200 | 1 | 1 | 1 |

每列使用自己的最小值和最大值，不能把整张表一起除以7200，也不要对每一行单独归一化。缩放处理数值尺度，并不说明三项属性对价格同样重要。[sklearn0.24 MinMax说明](https://scikit-learn.org/0.24/modules/generated/sklearn.preprocessing.MinMaxScaler.html)

本次用现有六模型核心做了16条、3属性的受控检查：一列时间从秒换成小时，在属性身份和专家评分不变、各自重新拟合相应scaler的条件下，两套模型预测最大差异约2.84e-14。它验证单位缩放不会凭空赋予大数更多重要性，不是业务精度测试。预测接口仍必须按模型声明的单位传值，不能把旧模型期待的秒直接换成小时数提交。

如果80和7200出现在同一属性列，则还要看其分布；仅因数值大就取对数没有依据。对明显右偏、跨度很大的正值列，可把log1p作为独立候选比较；温度等可为负数的列不能直接套用该规则。微样本下不建议默认加入大量分布变换和高自由度变换。

## 更重要的是1—5的含义

| 数据含义 | 合理处理方向 |
|---|---|
| 真实数量，例如1—5个通道 | 数值输入，保留数量含义；生成推荐时限制为整数 |
| 有顺序的等级，例如1—5级防护 | 保留顺序；已知合法范围时可比较固定映射(x−1)/4 |
| 材料或型号的类别代码1—5 | 明确作为无序类别处理；线性/SVR可比较独热编码，避免虚构距离 |
| 布尔值0/1 | 保留真假含义，候选生成只能取合法值 |
| 专家给属性的重要性评分1—5 | 单独配置价格先验，不能与上述样本属性值混为一列 |

当前V2对枚举采用固定数字编码，以保持提供版本行为；这不等同于已经消除线性模型中的类别距离假设。如果数据里包含无序编号，编码层是值得进一步改进的部分。不能仅凭“整数或不同取值少”自动判断类别，16条记录里实际数量也可能只有几个不同取值。

有序等级若只在训练集看到2—4级，普通MinMax会把2—4拉到0—1；若业务明确合法范围为1—5，固定范围映射可保持跨划分语义稳定。这是可比较的预处理选项，并不自动使模型学会未见等级。合法范围与历史已覆盖范围应分别保存。

生成方案时在原单位中约束整数、等级合法集合和类别，不因为模型内部使用浮点数就生成“材料编号3.7”。若更换编码，必须同步保存编码器、特征展开关系、原始英文代号与中文名映射，并重新验证原生包、单条/批量和导出后的预测一致性。

## 保持正确的处理顺序

推荐保持：属性类型及单位确认→训练部分的编码/缩放→价格专家倍率→基模型→价格尺度还原→融合。非恒定列上，先乘固定倍率再做MinMax会将这个倍率抵消，削弱线性模型与SVR中的专家先验。当前V2的先MinMax后专家加权顺序是正确的。

MinMax不要求新样本永远落在0—1：超出训练范围时可能出现负值或大于1，应记录外推提示。不要为了数值好看直接截断；预测时更不能对新表或单条记录重新fit。遇到少量极端值，可将RobustScaler列为对照候选，而不是因为存在7200这样的数就默认替换当前已验证的MinMax基线。[sklearn0.24预处理说明](https://scikit-learn.org/0.24/modules/preprocessing.html)

## 建议的优先级

先补充属性的连续数值、整数数量、有序等级、无序类别和布尔语义；保持现有MinMax/专家顺序与导出链。随后在搜索层借鉴历史复用、多个Pareto区域精修和权重重评缓存。以相同数据和预算比较原V2与二阶段版本，再决定是否切换默认搜索器。
