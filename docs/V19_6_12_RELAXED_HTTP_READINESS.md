# V19.6.12 双 HTTP 服务宽松准入与 V10 工作台兼容

## 准入原则

主推荐系统只把以下情况作为模型计算的阻断条件：

1. 价格 API 实际调用不能返回数值价格；
2. 效能 API 实际调用不能返回数值分数或可行概率。

Data Master 与模型 Schema 的字段类型、单位或绑定差异只作为告警。缺少的模型字段会尝试从服务 Schema 自动登记；登记失败也不取代真实 API 调用结果。

`CHECK_MODEL_SERVICES.bat` 不仅检查 `/health`，还会分别执行一次价格预测和效能评价。`product_code` 或 Schema 描述差异只告警，不阻断实际可用的 HTTP 服务。

## V10 效能兼容

V10 原运行时包使用包内固定协议，可以正常调用 `/api/v1/evaluate`，但不支持逐请求 `target_protocol`。独立效能工作台会识别该能力：

- V10：显示“模型包内固定协议”，不向服务发送 `target_protocol`；
- V11：允许选择内置协议或发送动态协议。

服务端也执行同样的兼容处理，因此即使浏览器缓存了旧前端，V10 评价也不会再因误传协议编号而要求升级。

## 启动顺序恢复

如果先启动主系统、后启动价格和效能服务，主系统会在重新打开页面或发起推荐时重新连接双服务。实算 JSON 成功后会自动恢复模型计算，无需重启主系统。
