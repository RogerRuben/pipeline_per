# V7 / V3+ 使用说明（2026-10-30）

本版以原V3六模型联合搜索为起点。保留原V3获分快照、全量模型、参数、权重和日志；新增少量候选的共同开发复核、训练种子平均、收缩融合和可选专家五档错分率。V2/V3/V4/V5.1/旧V5/V6均保留，推荐系统仍使用真实V21.6。

## 现场操作

完整离线包解压后START直接加载保存的虚拟演示，不训练。真实使用只需替换`input/products.xlsx`，执行CHECK_INPUT、RETRAIN；之后START使用保存模型，EXPORT导出当前模型、成品业务数据和固定环境，不需要原训练表。补丁覆盖旧V6包后执行APPLY_V7，原模型、输入和旧配置保留，新V7需要显式训练。

第一行中文名、第二行唯一英文代号，第三行起记录；价格为正，最低4条有效记录。属性只有number数值和enum配置两类。1—5、80、7200等不同量级由每次训练自己的MinMax处理；001/002等配置请声明enum。`价格属性评分`可带英文代号、中文名、价格重要性评分、属性类型列。该表、效能偏好和耦合关系均可选；没有耦合时不编造。

MODE_MENU支持所有版本及V7设置。V7_BALANCED为默认，V7_GOAL_FIRST优先原开发目标，V7_BASELINE_ONLY只运行原V3对照。原V3也有独立SELECT_V3入口。专家一致性可用V7_EXPERT_OFF/REPORT/SOFT/STRICT切换，改变模式后若没有该模式保存模型，START会要求先训练。CONSISTENCY阈值、训练种子个数和复核折数可在菜单及JSON调整。

COMPARE_V3_PLUS只读取当前已保存V7报告，输出同口径原V3/改进结果及逐候选记录，不重新训练；与原V3对照来自同一轮基线，因此无需再消耗一次搜索。该对照不代替真实新成品的独立验收。

## 价格路线

1. 使用同一份数据和明确的V3配置，完整执行NSGA-II→多锚点TPE，保留原模型和获分参数。V7不改写原V2核心，V3额外接口仅用于日志和检查点。
2. 记录少量不同参数/开发划分的优胜方案，默认候选池10、最多复核5套，另有原专家强度、弱专家和纯数据候选。完全相同参数不会因为划分种子不同而重复计为新参数方案。
3. 共同开发计划在新增拟合之前确定，不依价格选容易划分。16条默认4折，每次12条训练、4条验证；4—7条按配置组留一。相同输入配置不跨共同折，实际训练至少2条；单条验证R²为null，只计算拼接留出预测的总体R²。某候选必须完成整套共同折及原V3划分才有资格参与比较，部分成绩不入选。
4. 比较共同开发MAPE、R²、尾部误差、波动及原划分开发成绩。新增方案的共同开发MAPE不高于原V3参数同条件复核值；默认允许原划分MAPE增加最多1个百分点、R²降低最多0.02。这些界限可配置，未发现合适增强则返回原V3模型，并明确记录没有升级。
5. 最后少量候选可使用事先声明的3个训练种子。只有ExtraTrees和GBDT重复拟合，确定性模型复用；平均原价格空间预测，不挑最好的种子，某种子失败不会悄悄删除后再平均。种子个数及范围均可配置。
6. 六模型原份额允许在共同留出预测上做有正则、有限移动的调整；小于6条独立记录不学习连续新份额。还可用已有预测做有限的单成员移除对照：只有移除前后总权重变动不超过设定上限、共同开发及原划分保护条件均满足才参与最终选择，差成员可降为0，不增加复核拟合。最多融合3个参数方案，份额非负且和为1。实际全量模型重新检查训练成绩、导出预测等价和可选专家指标。

原V3的`split_seed`是开发划分种子；ExtraTrees/GBDT原始训练种子固定为0。V7新增的是另一层训练随机性平均。两类种子在报告中分别记录。

## 专家五档可选指标

专家评分为价格属性重要性1—5整数分，同分属于同一档，不要求档内顺序。错档率为`错档属性数/明确已评分属性数×100%`；例如36个已评分属性最多3个错档，40个最多4个。未提供的专家评分不作为真实专家1分参与一致性考核，报告显示覆盖率；严格模式默认要求覆盖全部属性。

实际重要性统一测量整个集成模型的价格响应：在固定的参考输入范围内，按固定置换安排改变一个原始属性，统计价格预测变化，归一化为占比。计算不使用真实价格标签，不混加线性系数与树的重要性；独热编码合回原英文属性。它描述模型在参考范围内对属性的依赖，不代表因果作用或独立预测准确性。

分档规则在搜索前固定为“专家各档数量对应的重要性排名区间”。只使用各档数量作配额，模型自己计算的实际重要性决定排序；不使用某属性的专家标签给它安排模型档位。实际重要性数值和分档同时导出，禁止为了达标修改展示值。跨档边界的重要性持平会标记无法确定，不按专家答案破同分；所有评分只有一档、模型所有响应为0时，不宣称已证明五档一致。严格模式遇到无法确定档位不算通过。

| 模式 | 行为 |
| --- | --- |
| off，默认 | 不计算该指标，不改变选模 |
| report | 计算实际部署模型的错档率，只报告 |
| soft | 价格目标优先，价格表现相近时对错档加温和惩罚 |
| strict | 价格训练/原划分开发及专家错档率同时满足才标记达标 |

仅对少量实际全量候选计算重要性，置换预测按批处理。高相关或几乎不变的属性可能无法区分；无法满足约束时保留诊断，不假造一致性。严格发布可设`publish.policy=require_targets`；否则允许导出清晰标记的未达标草稿。

## 指标及独立性

报告分开列出原V3训练、原V3获分开发、原V3参数的共同CV、改进方案的原划分开发、共同CV和实际部署训练。V7沿用V3的目标语义：默认要求部署训练及原划分开发MAPE≤10%、R²≥0.9；共同CV用于比较并单独报告是否达标，不伪装成独立测试。

共同开发复核、融合份额与专家约束都参与选择。报告明确`independent_test_provided=false`，独立测试指标为空。不可把重新全量训练后的模型套回训练记录再称测试。保留原V3高分并不证明新成品泛化；真实效果要用未参与本轮设计的新记录检验。V6的固定留出等已有评估模式仍可切换使用。

## 预算、恢复与追溯

标准原V3预算300个配置，900秒；QUICK为40配置/300秒，DEEP为5000配置/1800秒，达到时间时以已完成试验为准。新增拟合预算默认约为原V3实际拟合的20%，为低预算启动至少预留96次，标准最多500次/180秒；QUICK上限128次/90秒，DEEP上限1000次/300秒。实际拟合尝试、失败和缓存命中分别记录；单次拟合或最终文件导出可能使墙钟时间略超软预算。

预算不足时减少新增候选，不缩掉未完成的折来充当完整成绩，也不覆盖原基线。原V3、共同折、候选、训练种子、份额、接纳/拒绝、实际导出、每条训练预测和专家档位均有记录。长步骤输出心跳，保留小误差有效数字。

检查点包含数据、代码、配置、环境及文件摘要；RESUME可恢复V3搜索状态、已完成基线和新增成员缓存，完成后的同模式恢复为零新增拟合。成功结束后默认清理逐成员缓存，保留基线、最终模型和审计报告。新增时间预算按本次运行计算，fit尝试跨恢复累计。原V3数据、配置与代码完全相同时，不同V7模式可复用同一已校验基线；新增预算或协议变动建立新标识，不混接不同配置结果。EXPORT不携带搜索缓存。

运行环境固定Python3.8.10 x64、sklearn0.24.2、Optuna3.6.0；不增加新训练库。V21.6门户、四服务生命周期和专家效能导入接口沿用已验证实现。虚拟演示及外部虚拟数据对照仅供检验软件和方法边界，不能作为真实业务精度承诺。
