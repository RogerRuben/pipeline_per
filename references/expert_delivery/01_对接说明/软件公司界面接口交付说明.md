# 软件公司界面接口交付说明

交付日期：2026-09-04  
交付基线：锁成品特化 V17、泵系统级特化 V13

## 1. 本次交付目的

本包用于软件公司开发集中统一界面，并理解两类效能模型如何训练、如何评价和如何解释结果。

本次不修改任何算法、模型格式、Excel 契约、状态格式或后台接口，只调整两套演示应用的信息架构和评价可视化：

1. 首页统一为`方案效能评估`。
2. 第二页统一为`UTA模型训练`。
3. 删除页面最上方的大标题，仅保留项目、任务或基准上下文。
4. 评价结果优先展示效能总分、评分构成、属性贡献、效能曲线和文字解释。
5. 泵系统级的物理可行性、耦合和公式诊断保留，但降为折叠的辅助信息。

## 2. 两套应用的定位

| 应用 | 评价对象 | 100 分口径 | 核心输出 |
|---|---|---|---|
| 锁成品 V17 | 舱门锁成品方案 | 当前选定基准技术协议 | 相对效能分、整机复用结论、单项复用状态、扣分贡献、迁移曲线 |
| 泵系统 V13 | 泵方案对液压系统任务的贡献 | 当前系统要求的中性参考 | 系统综合效能、任务适配、成品固有性能、要求差距、属性加减分、跨任务表现 |

两套应用不能共用同一个冻结模型，也不能把锁的`不可复用`解释成泵的`物理不可行`。

## 3. 统一界面建议

集中界面的一级入口使用`方案效能评估`。建议按以下顺序展示：

1. 待评价方案输入和基准/系统任务选择。
2. 综合效能分与结论。
3. 属性效能加减分或扣分贡献。
4. 每个属性的效能曲线与当前方案落点。
5. 逐项评分解释账本。
6. 稳健区间、迁移把握或复用余量。
7. 物理可行性、耦合、公式和开发诊断作为辅助折叠内容。

`UTA模型训练`是模型形成和追溯页面。最终生产软件如果只部署冻结模型，可以不向普通用户开放该页；本交付版保留完整训练页，便于软件公司理解模型来源和进行联调。

## 4. 当前网页接口

### 4.1 锁成品 V17

入口：`lock_v17_app.py`  
页面：`lock_ui.html`

```text
GET  /api/state
POST /api/evaluate
```

评价请求：

```json
{
  "params": {
    "load_capacity": 48.0,
    "hook_lock_force": 38.0,
    "unlocking_force": 30.0,
    "tolerance": 1.5,
    "adaptability": 6.5,
    "trigger_force": 8.0,
    "mass": 13.0
  }
}
```

属性 ID、单位和可选评价基准必须读取项目或冻结模型契约，不能把示例字段写死在统一软件中。

### 4.2 泵系统 V13

入口：`system_app.py`  
页面：`system_ui.html`

```text
GET  /api/state
POST /api/evaluate
```

当前演示网页的评价请求为扁平对象：

```json
{
  "pump_pressure": 21.0,
  "pump_flow": 45.0,
  "pump_weight": 22.0,
  "rated_power": 18.0,
  "working_time": 1200.0,
  "pulse_pressure": 31.0
}
```

正式集中软件优先直接调用冻结运行时，不建议把训练应用的本机 HTTP 接口固化为跨软件长期协议。

## 5. 正式冻结模型接入

### 5.1 锁成品模型

专家完成训练后导出：

```text
lock_v17_reuse_model_<摘要>.zip
```

模型格式：`lock-product-reuse-model-17.0`  
运行类：`FrozenLockReuseRuntime`  
模型文件：`model/frozen_lock_reuse_model.json`

正式界面主要读取：

- `effectiveness_score`
- `effectiveness_interval`
- `overall_reuse_status` / `overall_reuse_label`
- `combined_reuse_threshold`
- `attributes`
- `loss_contributions`
- `migration`
- `visualization.marginal_curves`

### 5.2 泵系统模型

专家完成训练后导出：

```text
system_effectiveness_model_<摘要>.zip
```

模型格式：`system-effectiveness-frozen-model-13.0`  
运行类：`FrozenSystemRuntime`  
模型文件：`model/frozen_system_model.json`

正式界面主要读取：

- `system_assessment.decision_score`
- `system_assessment.continuous_score`
- `system_assessment.direct_score`
- `system_assessment.product_score`
- `system_assessment.direct_assessment.attributes`
- `system_assessment.product_contributions`
- `system_assessment.top_contributors`
- `system_assessment.task_transfer`
- `system_v13_visualization`

泵模型允许在相同属性结构下切换已配置任务，或传入系统要求覆盖并即时重算；不应通过直接修改总分模拟新任务。

## 6. 当前包和正式模型的边界

当前包包含演示 Excel 和完整训练/评价源码，可用于：

- 查看最终评价首页；
- 对照实现统一界面；
- 调试输入、输出和图表；
- 理解 A/B 判断如何形成 UTA 模型；
- 运行自动测试。

当前包不包含：

- 甲方真实 Excel；
- 甲方专家 State；
- 逐条专家判断和自由文字；
- 甲方正式冻结模型。

正式上线前，必须把演示模型替换为甲方返回的对应冻结模型 ZIP，并用同一输入对比专家软件与集中软件的评分是否一致。

## 8. 联调验收标准

1. 启动后默认显示`方案效能评估`，`UTA模型训练`位于第二页。
2. 页面顶部没有产品版本大标题。
3. 锁版基准方案评估为 100 分；模型未训练完整时必须保留不确定提示。
4. 泵版能同时展示综合效能、任务适配和成品固有性能。
5. 每项属性贡献与总分账本一致。
6. 各属性曲线能标出当前方案位置。
7. 冻结运行时与专家应用对相同输入给出一致结果。
8. 更换模型必须整包替换并校验模型格式、摘要和 SHA-256，不得手工编辑模型 JSON。
