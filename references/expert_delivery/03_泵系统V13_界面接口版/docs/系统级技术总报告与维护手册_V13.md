# 系统级效能评价 V13 技术总报告与维护手册

## 1. 目标

V13 面向泵到液压系统的效能评价，同时解决两个表面矛盾的目标：先把当前系统要求附近学准，又必须一次训练得到可迁移到高低规格任务的全域模型。

## 2. 双通道评分

直接系统属性包括压力、流量和重量。它们依赖具体任务要求，构成任务适配效用 `U_direct`。其他成品属性构成跨任务共享的固有性能效用 `U_product`。

```text
U_system = alpha * U_direct + (1 - alpha) * U_product
```

`alpha`、属性权重和边际形状由稳健联合 LP-UTA 学习；系统要求的 100/80 工程锚点固定，不允许学习过程把严重失配托成虚高单项分。硬性策略在连续效能之后形成最终决策效能。

## 3. 全域多工况训练

### 3.1 自动主规格

`PumpRegionPlanner` 在直接映射属性中选择正值对数跨度最大、且要求为 `at_least` 或 `relative_higher` 的属性。泵数据会自然选中流量，但代码没有写死字段名。

### 3.2 自动分区

根据生成范围、历史范围和真实任务锚点建立 1 到 5 个代表区域。跨度大时使用对数均匀中心和几何中点边界，避免 1 到 70 的低值区域被线性尺度压缩。

训练顺序为：真实任务所在区域优先，其余区域按与当前任务的对数距离由近到远补齐。

### 3.3 区域校准任务

每个区域有独立的内存校准任务：主规格要求移动到区域中心，主规格评分尺度同比缩放；上限型预算属性根据历史对数斜率缩放。校准任务只定义专家当前判断语境，不写回 Excel。

### 3.4 同带 A/B

生成器先选本区域历史锚点；若区域没有历史实物，则以现有可行方案为基础生成公式和耦合一致的区域锚点，并明确标记为待专家判断。A/B 候选都经过区域边界检查，跨带候选被惩罚或替换。

区域完成后清空跨区域胜者链，下一区域重新选择 A，防止高规格 A 永久支配低规格比较。

## 4. 模型结构

### 4.1 共享模型

全部有效比较进入共享联合 LP-UTA。每条证据保存当时的 `system_task_snapshot`，因此同一优化问题可以按各自工况把 A/B 转成无量纲任务满足向量，再共同求解全域趋势。

### 4.2 区域模型

每个区域用本区域证据训练一套相同结构的联合 LP-UTA。区域证据少时不允许完全替代共享模型。

### 4.3 分层收缩与插值

评价任务与各校准任务计算无量纲距离，选择最近两个区域。区域直接属性增量先加权平均，再按证据量收缩到共享增量，区域最大占比为 70%。邻近两区属于插值，超出覆盖范围属于外推并降低迁移把握。

成品固有性能增量始终来自共享模型，避免跨任务重复学习稳定偏好。

## 5. 可行性、公式和复核

- 历史实物是自身 100% 可行硬锚点，不被当成整条方程。
- 物理前沿由可行和不可行证据从两侧夹逼，支持最小前沿、最大前沿、硬带和经验趋势。
- “可行但低效率”与不可行负例分开。
- 不可行夹逼同时改变源和目标属性，避免只重复原单属性问题。
- 公式用安全 AST 白名单执行，支持比例、效率或仿射校准，候选生成后统一回算。
- 复核重新载入原 A/B，新证据只替换目标判断，保留审计历史。
- 复核 ID 在完整 State 中全局分配；V12 跨任务重号会被幂等迁移并保留 `original_review_id`。

### 5.1 因果聚焦证据

V12 候选生成器按主动改变的独立属性识别控制变量题，但覆盖统计曾按最终变化的全部 UTA 组判断。泵的压力或流量变化会被动联动重量并触发功率公式回算，因此有效问对被错误排除在可靠覆盖之外。

V13 在每条偏好证据中保存 `active_driver_keys`、`passive_changed_keys`、`coupling_derived_keys` 和 `formula_derived_keys`。可靠覆盖的聚焦条件改为主动设计变量为 1 至 2 个；已知耦合和公式造成的被动变化不会使证据失效。每个槽位仍需至少两条证据，且至少一条为因果聚焦证据。

区域近要求覆盖门槛为 65%。对于 6 个离散近要求槽位，这表示至少 4 个槽位已有证据，避免 70% 门槛在离散计数上实际跃迁为 5/6，即 83%。全域阶段仍继续补齐其余曲线。

## 6. 未知方案评价

评价端始终使用真实任务，不使用训练校准任务。输出包含任务适配、成品固有性能、连续效能、最终决策效能、系统要求账本、公式和物理解释。

V13 可视化包括六属性平滑展示曲线、当前落点、跨代表工况评分、区域敏感性和流量-重量历史散点。展示曲线使用平滑插值，开发者折叠区保留可审计的原始分段节点；正式评分仍严格使用原始分段函数。

## 7. 状态与冻结模型

State 保存共享模型、区域列表、区域模型、区域胜者、区域完成进度、每条证据的区域 ID 和任务快照、复核、可行性、公式与评价历史。V13 为迁移兼容而沿用 `system_v12_pump_` 文件名前缀，以 `system_profile_version=13` 区分新结构；V12 State 首次加载后会补齐因果字段、修复复核编号并重训。V11 及更早 State 不兼容。

冻结模型保留推理所需的共享与区域参数、映射、公式和物理模型，但移除完整点击与自由文本。在线端和冻结端使用相同的邻近区域选择、收缩和插值逻辑。

## 8. 维护入口

- 改分区阈值或区域数量：`regional_context.py` 的 `_region_count`、`MAX_REGIONS`。
- 改预算缩放：`regional_context.py` 的 `_weight_exponent` 和 `_calibration_task`。
- 改区域完成门槛：`system_app.py` 的 `regional_progress`。
- 改收缩强度和邻区数量：`system_app.py` 与 `frozen_system_model.py` 的上下文模型组合逻辑，必须同步修改。
- 改候选生成：`system_app.py` 的 `regional_anchor`、`_regional_vector`、`select_candidate`。
- 改评分锚点：`hierarchical_uta.py`，同时执行 V11 要求锚点测试。
- 改未知评价图：`unknown_visualization_payload` 和 `system_ui.html`。
- 改 Excel 契约：`system_excel.py`，不得在业务代码写死泵属性名。

## 9. 修改纪律

1. 不覆盖 V11 或旧封盘目录。
2. 在线和冻结推理的区域组合算法必须同改同测。
3. 训练校准任务与真实评价任务必须保持分离。
4. 平滑曲线只能用于展示，不能偷偷替换审计评分函数。
5. 新增状态字段时升级版本契约并补冻结导出。
6. 修改后至少运行 `python -m unittest discover -v`。

## 10. 已知边界

- 区域模型是主动学习和分层收缩模型，不是从极少样本中恢复真实连续物理定律。
- 自动预算缩放依赖历史数据，样本极少时只是保守工程先验。
- 区域敏感性表示模型间差异，不应宣称为严格统计置信区间。
- 离已学习区域过远的新任务可以评分，但必须展示较低迁移把握，必要时补少量迁移验证。
