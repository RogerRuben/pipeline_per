# 锁成品 V17 冻结模型调用说明

## 1. 冻结包是什么

专家完成训练后，点击“导出冻结复用模型”，得到：

```text
lock_v17_reuse_model_<摘要>.zip
```

ZIP 用于交给其他软件调用未知方案评估，不是完整训练档案。

主要内容：

```text
lock_v17_runtime_manifest.json
model/frozen_lock_reuse_model.json
source/frozen_lock_model.py
source/lock_utility_model.py
source/preference_models.py
source/project_excel.py
00_冻结模型说明.txt
```

冻结包不包含原始 Excel、历史方案行、逐条专家点击、专家文字、复核历史或未知方案评价记录。

## 2. Python 调用

解压 ZIP，把 `source` 加入 Python 模块路径：

```python
import sys
from pathlib import Path

package = Path(r"D:\lock_v17_model")
sys.path.insert(0, str(package / "source"))

from frozen_lock_model import FrozenLockReuseRuntime

runtime = FrozenLockReuseRuntime(
    package / "model" / "frozen_lock_reuse_model.json"
)

params = {
    "load_capacity": 48.0,
    "hook_lock_force": 38.0,
    "unlocking_force": 30.0,
    "tolerance": 1.50,
    "adaptability": 6.5,
    "trigger_force": 8.0,
    "mass": 13.0,
}

# 不传 profile_id 时，默认相对训练主基准评价。
result = runtime.evaluate(params)

# 也可选择冻结模型中携带的较低评价基准，不需要另一套训练模型。
result_lower = runtime.evaluate(params, profile_id="REQ-DEMO-02")
print(result["effectiveness_score"])
print(result["overall_reuse_status"])
print(result["attributes"])
print(result["loss_contributions"])
```

输入键必须使用冻结 schema 中的属性 ID，不能使用界面中文名。所有属性必须完整，单位必须与训练 Excel 一致。

可用基准在模型 JSON 的`evaluation_baselines`中，每项包含`profile_id`、名称和参数。调用方不得自行构造不存在的`profile_id`。

## 3. 关键输出

| 字段 | 含义 |
|---|---|
| `effectiveness_score` | 相对 100 分基准的效能分，范围 0 至 100 |
| `effectiveness_interval` | Bootstrap稳健模型给出的P10至P90分数区间 |
| `overall_reuse_status` | `reusable`、`not_reusable`或`uncertain` |
| `overall_reuse_label` | 中文整机复用结论 |
| `combined_reuse_threshold` | 专家数据学到的综合复用分界 |
| `single_attribute_violations` | 明确超过单项边界的属性 |
| `uncertain_attributes` | 单项边界尚未完成或位于夹逼区的属性 |
| `attributes` | 每项基准值、当前值、退化量、单项极限和状态 |
| `loss_contributions` | UTA 权重、当前效用和逐属性扣分 |
| `migration` | 主基准或曲线形状迁移状态、置信标记和诊断对照分 |
| `visualization.marginal_curves` | 主曲线、迁移后曲线、证据支持区、方案落点和迁移后极限 |
| `physical_feasibility_evaluated` | 永远为 `false` |

软件公司通常直接展示总分、整机复用结论、每项复用状态和扣分贡献。不要把`not_reusable`翻译为“物理不可行”。

## 4. 完整性校验

加载器会检查：

- `model_format = lock-product-reuse-model-17.0`；
- 必需字段完整；
- `model_digest`与内容一致；
- 隐私声明不含训练记录；
- 属性退化维度与运行时一致。

任何校验失败都应停止评分，不能忽略后继续运行。

## 5. 模型更新

继续训练后重新冻结会生成新的摘要和版本号。调用方应：

1. 保留原 ZIP，不手工编辑 JSON。
2. 校验 manifest 中的格式、产品代号、模型摘要和文件 SHA-256。
3. 用固定验收输入比较新旧结果。
4. 整包原子替换，失败时回滚。
5. 记录生产环境当前使用的`model_version`和`model_digest`。

修改属性ID、单位、生成范围、偏好方向、训练主基准或UTA分段数后，旧冻结模型不能与新输入结构混用。只新增或修改较低评价基准时无需重新训练，但必须重新冻结并替换模型，才能让调用方获得新的`profile_id`和迁移参数。

## 6. 与完整训练档案的区别

完整训练档案用于：

- 恢复专家点击；
- 继续训练；
- 查看复核和学习过程；
- 内部审计。

冻结模型用于：

- 嵌入最终软件；
- 批量评价未知方案；
- 给推荐或筛选模块提供效能分和复用结论。

冻结模型不能继续训练，也不能还原专家逐条判断。
