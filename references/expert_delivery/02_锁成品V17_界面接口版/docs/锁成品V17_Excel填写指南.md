# 锁成品 V17 Excel 填写指南

## 1. 工作表

推荐保留以下五张表：

```text
项目信息
方案数据
属性配置
耦合关系
基准技术协议
```

V17 直接使用`项目信息`、`方案数据`、`属性配置`和`基准技术协议`。`耦合关系`可为兼容 V15 保留，但 V17 不使用它学习或输出结论。

示例：`data/product_v17_lock_demo.xlsx`。

## 2. 项目信息

使用两列键值形式：

| 第一列 | 第二列示例 |
|---|---|
| 成品代号 | `AIRCRAFT_DOOR_LOCK_01` |
| 成品名称 | `某型舱门锁效能评估` |

成品代号应稳定，正式训练后不要随意修改。

## 3. 方案数据

第一行固定包含：

```text
方案编号 | 来源 | 已知可行性 | 属性1 | 属性2 | ...
```

属性列名称必须与`属性配置`的“属性名”完全一致。

V17 不依靠历史样本学习物理可行性。历史样本主要用于项目数据完整性、非训练属性缺值时的展示补齐和后续审计。即使样本很少也能启动本流程，因为核心证据来自基准退化后的专家判断。

## 4. 属性配置

每个属性一行。关键字段：

| 字段 | 填写方法 | V17 中的作用 |
|---|---|---|
| 属性名 | 与方案数据表头一致 | 界面显示和跨表匹配 |
| 属性ID | 稳定英文或拼音，不重复 | 冻结模型接口字段名 |
| 单位 | 统一工程单位 | 显示和调用校验 |
| 数据类型 | 连续、整数或类别 | 数值属性才能训练 |
| 设计顺序 | 1、2、3 | 学习初期的权重先验，后续由专家偏好修正 |
| 显示精度 | 0、1、2、3等 | 生成值和界面显示精度 |
| 生成下限 | 允许试探的最小值 | 定义无量纲退化尺度 |
| 生成上限 | 允许试探的最大值 | 定义无量纲退化尺度 |
| 偏好方向 | 越大越好、越小越好、区间型 | 决定从基准向哪边变差 |
| 边际规律 | 可填边际收益递减、边际损失加速等 | 作为 LP-UTA 形状约束 |
| 参与效能 | 是/否 | 是否进入 UTA |
| 参与生成 | 是/否 | 是否由生成器主动试探 |

`可行下限`和`可行上限`可保留以兼容旧版，但 V17 不把它们解释为物理可行边界。

### 4.1 偏好方向

- `越大越好`：低于基准是退化。生成下限决定最差试探边界。
- `越小越好`：高于基准是退化。生成上限决定最差试探边界。
- `区间型`：基准值是最佳点，向低值和高值两边都要分别学习边界。
- `不参与`或`待确认`：不进入 V17 训练。

例如重量越轻越好，应填`越小越好`；额定载荷越大越好，应填`越大越好`；必须接近某个规定值的指标，应填`区间型`，并在基准技术协议中填写最佳值。

### 4.2 生成范围

生成范围不是可行范围，而是专家愿意让软件试探的最外层区间。

- 100 分基准值必须位于生成下限和生成上限之间。
- 范围太窄会找不到真正不可接受点。
- 范围过宽不会改变单位影响，因为软件按“基准到最差边界”的比例归一化，但可能增加前几次问题跨度。
- 不同量纲不会直接互相干扰，2.2 和 11000 都先转成 0 至 1 的退化比例。

若基准值超出生成范围，V17 会拒绝启动并指出具体属性，不会静默修改 100 分基准。

## 5. 基准技术协议

一行表示一份可选的 100 分评价基准：

```text
协议编号 | 协议名称 | 属性1 | 属性2 | ... | 说明
```

要求：

1. 每个参与训练的数值属性都填写基准值。
2. 属性方向不在这里重复填写，直接沿用属性配置。
3. 基准值必须位于该属性生成范围内。
4. 协议编号稳定且不重复。

第一行必须放性能最高、专家准备围绕它训练的“主基准”。软件的A/B题只使用这一行，并只训练一次。其余行可以放较低技术协议，供未知方案评价时选择；软件会迁移主基准已经学习的逐属性UTA曲线形状和相对复用极限，不要求重新点击。

评价基准应与主基准使用同一属性结构、单位和偏好方向，并位于原生成范围内。较低基准是指：`越大越好`属性不高于主基准，`越小越好`属性不低于主基准。若某项评价基准反而优于主基准，软件会标记为不支持直接迁移。

新增或修改第二行以后的评价基准不会切换训练State，但应重新导出冻结模型，调用方才能看到新基准。修改第一行主基准、属性ID、单位、偏好方向或生成范围仍会形成新学习指纹，需要重新训练。

## 6. 耦合关系

可以保留旧 Excel 中的耦合关系，但 V17 明确忽略：

- 不生成耦合联动方案；
- 不询问可行或不可行；
- 不学习物理前沿；
- 不在未知方案中输出耦合依据。

需要这些能力时使用成品 V15，而不是修改 V17 标签含义。

## 7. 提交前检查

1. 工作表名称正确。
2. 属性名在三张表中完全一致。
3. 属性 ID 稳定、唯一、无空格。
4. 单位统一，数值单元格中不写单位文字。
5. 设计顺序只填 1、2、3。
6. 生成下限小于生成上限。
7. 第一行是唯一训练主基准，其余行只作为未知方案评价基准。
8. 所有基准值位于生成范围内，评价基准没有优于主基准的属性。
9. 参与效能且参与生成的属性具有明确偏好方向。
10. 目标点型属性使用`区间型`，不要写成越大越好或越小越好。
11. 正式训练后不要修改属性ID、单位、生成范围或主基准值；确需修改时建立新项目重新训练。
